Wireless Network Security Audit

WEP key recovery and an introduction to WPA/WPA2 decryption, performed in a Kali Linux lab environment.

← Back to projects

Project Overview

In this lab, I performed a wireless network security audit focused on recovering a WEP (Wired Equivalent Privacy) encryption key from a captured packet file, using the industry-standard Aircrack-ng suite inside a Kali Linux workstation.

The goal was to understand, hands-on, why WEP is considered broken and how penetration testers use packet analysis and statistical attacks to recover legacy Wi-Fi keys.

  • VM used: Kali – Internal Workstation
  • Capture file: lab5wep-demo.cap
  • Target network: ccni-test (WEP-encrypted)
  • Primary tool: Aircrack-ng suite

Work Completed

1. Opening the Capture File

I opened Kali – Internal Workstation and navigated to the lab resources to locate the capture file for this exercise: 

cd /root/.cache/.fr-xiWTPy/Lab\ Resources/Module\ 5/

The backslashes tell Linux that the space is part of the folder name rather than the start of a new command — an important detail when navigating directories with spaces in their names.

2. Navigating Wireshark

I opened lab5wep-demo.cap in Wireshark to review the captured 802.11 wireless frames. A packet is a small, formatted chunk of data traveling across a network — the same kind of unit that carries videos, pictures, and emails.

Reviewing the 802.11 frames surfaced three important concepts:

  • Beacon Frame: the signal a router sends out roughly every 100 milliseconds to announce "I'm here, and here's how to connect to me" — similar to a lighthouse flashing its light.
  • The "To Everyone" address: because the router broadcasts into the air for any nearby device to hear, the receiver and destination addresses are set to broadcast (ff:ff:ff:ff:ff:ff) so no device is left out.
  • The router's ID (BSSID): the router's unique hardware address, so devices know exactly which physical device is broadcasting the signal.
  • Sequence number: a tracking number that keeps frames in the right order and ignores duplicates if interference scrambles something in the air.

3. Using the Aircrack-ng Suite

Aircrack-ng is used to perform complete wireless network security auditing and penetration testing. It comes with a collection of complementary tools:

  • airmon-ng: enables and disables monitor mode on a wireless card, letting the computer listen to all nearby Wi-Fi traffic instead of only traffic meant for it.
  • airodump-ng: captures packets, scans surrounding wireless networks, and displays active access points — their BSSIDs, channels, and encryption types — along with connected clients.
  • aireplay-ng: injects frames into a wireless network to generate traffic, deauthenticate legitimate users, or speed up packet collection (such as WEP IVs).
  • aircrack-ng (core tool): processes the captured .cap or .ivs files to recover the pre-shared key or WEP password.

4. Running Aircrack-ng

With the capture file located, I opened a terminal and ran: 

aircrack-ng lab5wep-demo.cap

The output displayed a list of every Wi-Fi network found inside the capture file. In a real-world scenario, this is the same list an attacker would see — a neighborhood-wide list of nearby routers and their encryption types.

After the "Index number of target network" prompt, I selected the target network by entering 1.

5. Key Recovery

Aircrack-ng processed the capture and recovered the WEP key for the ccni-test network: 

SUCCESS!
KEY FOUND! [ F2:C7:BB:35:B9 ]

This is the exact WEP encryption key for the target network. In a real-world penetration test, entering this key into a Wi-Fi prompt would grant full access to the network.

Key Takeaways

🔓 WEP Is Broken

WEP encryption is fundamentally insecure because of a mathematical weakness in how it reuses Initialization Vectors (IVs). That weakness lets statistical analysis tools like Aircrack-ng recover the password in seconds — which is why WEP has been deprecated in favor of WPA2/WPA3.

⌨️ Command-Line Control Matters

I practiced navigating Linux directories with cd and running wireless auditing tools against specific networks (by BSSID) directly from the terminal.

📡 Wi-Fi Is Inherently Public

Routers constantly announce their presence through Beacon Frames and the broadcast address (ff:ff:ff:ff:ff:ff), meaning anyone nearby can detect and audit surrounding networks — a reminder of why strong, modern encryption matters.

✅ Hands-On Validation

I confirmed the attack worked by extracting and verifying the exact recovered key (F2:C7:BB:35:B9) with 100% accuracy.

This exercise reinforced why legacy encryption standards like WEP should never be used in production networks, and gave me practical experience with the packet-capture and auditing workflow (Wireshark + Aircrack-ng) used by security professionals to assess wireless network risk.
